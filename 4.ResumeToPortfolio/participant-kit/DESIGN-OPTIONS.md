# Explore a portfolio, then choose its URL

Open a few of these real websites. Pick one you like and paste its address into the build prompt. You can also bring any public website URL of your own. The reference supplies visual inspiration; your approved résumé supplies all personal facts.

**Choose the look, not the size of someone else's career.** You do not need as much content, a blog, a publication archive, or all the pages shown on these sites. AI will adapt the personality to your own résumé and a focused one-page portfolio. You can add or remove sections later with one sentence.

## What choosing each reference could bring to your site

These are suggested adaptations of observed homepage styling, not promises to copy a whole website. Desktop opening views were visually checked on November 1, 2026. Themes can vary, and mobile layouts, deeper pages, motion, and the final implementation still need checking when you select a reference.

**Want a quick starting point?** Try Seán for soft and expressive, Brittany for structured and professional, or Cassidy for compact and personal. You can select any style regardless of your profession. You can also paste a different public URL.

**Bonus playground — [Bruno Simon](https://bruno-simon.com/):** a driving-game world makes the portfolio itself an experience. A workshop adaptation could borrow its sense of exploration and playful section reveals while keeping a normal, readable one-page site. A complete 3D driving game is a separate scope decision. Its text and controls were reviewed earlier; full interaction and mobile testing remain outstanding.

You do not need to fill every panel shown on a reference site. Two strong highlights can be enough. If you want, add one sentence such as “Use Seán's soft colors, but keep my page as compact as Cassidy's.” Start with one main reference to keep the first build predictable; mixing details is optional later.

## AI reference workflow

1. Inspect the selected URL in a rendered browser at desktop and phone widths where tools allow. Look at composition, typography, colors, spacing, hierarchy, and interactions. Markdown-only extraction does not establish those visual details.
2. Prefer the connected Firecrawl plugin for branding extraction (font families, sizes/weights, colors, spacing) and a screenshot where its exposed tools support them. Check actual capabilities first: the service API supporting a format does not prove the plugin exposes it. Supplement with rendered browser inspection, especially for actual font rendering, responsive layouts, and interactions. General search finds references; it does not verify their visual styling. If Firecrawl is unavailable, use the browser/screenshot fallback without requiring paid access or manual MCP setup. Report unavailable outputs and any font substitutions; extraction is not a guarantee of exact reproduction.
3. If visual access fails, state that limitation and request a screenshot of the page/section the participant likes. Do not pretend extracted text is a visual inspection.
4. Record the original URL, evidence inspected, three to five specific qualities to borrow, and adaptations in DESIGN.md. Briefly tell the participant the direction. Ask only if there is a material ambiguity or the requested interaction would substantially expand scope.
5. Default to a single page with résumé-derived sections, omit unsupported/empty sections, and do not inherit the reference's site map, content volume, or blog. Do not require a section-selection questionnaire. Accept participant requests to add, remove, or rename sections. Build an original composition using approved résumé content. Do not import the reference owner's identity, writing, logos, photos, testimonials, or unsupported achievements. Use appropriately reusable assets only.
6. Compare the preview with the recorded qualities and fix the most visible mismatches. This is visual inspiration, not a source-code or exact-clone workflow.
