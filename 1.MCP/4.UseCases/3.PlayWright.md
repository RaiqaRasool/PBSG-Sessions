# Playwright MCP: Test Like a User

## Why this is useful

A browser test is more convincing when everyone can see the actions and the checks. This example turns a user journey into a repeatable task with a pass-or-fail report.

## How it works

Playwright itself can interact with the browser's DOM and query elements using things such as roles, labels, text, test IDs, and CSS selectors.

Microsoft's Playwright MCP specifically emphasizes using the browser's accessibility tree/structured accessibility information rather than relying primarily on screenshots and vision.

## Setup

Add the Playwright MCP server:

```bash
codex mcp add playwright \
  -- npx -y @playwright/mcp@latest
```


## Start with inspection

Copy this prompt into Codex:

```text
Use the Playwright MCP server to open http://localhost:3000.

Inspect the page and tell me what main UI elements are available.
Do not modify anything.
```


Next, ask it to explore the primary workflow:

```text
Use Playwright MCP to open http://localhost:3000.

Navigate through the main user flow, interact with the page like
a normal user, and report any obvious UI or functional problems.
Do not modify the code.
```

```text
                    Agent
                      │
          ┌───────────┴───────────┐
          ▼                       ▼

     Playwright MCP          Computer Use
          │                       │
       Browser                  Screen
          │                       │
   Web applications       Almost any GUI


Playwright:

“Give me structured control over a browser.”

Computer Use:

“Give me mouse/keyboard/visual control over a computer interface.”

Computer Use → visual, general purpose interaction

Playwright MCP → structured, browser specific, developer friendly automation
```


## Run a complete, verifiable workflow

Copy this prompt when the demo application is running at `http://localhost:8000`:

```text
Use Playwright MCP to test the application at http://localhost:8000.

Act like a user and:

1. Inspect the page and describe the available controls.
2. Add a task called "Prepare MCP presentation".
3. Verify that it appears in the task list.
4. Mark that task as completed.
5. Select the Completed filter and verify that the task appears.
6. Delete the task.
7. Try adding an empty task and verify that the validation message appears.

Report whether each step succeeded.

Do not inspect or modify the source code. Test the application entirely through the browser using Playwright MCP.
```

## What to notice

- Each action is followed by something observable that can be verified.
- The prompt defines the testing boundary: browser only, with no source-code access.
- The final report makes failures easier to reproduce and discuss.
