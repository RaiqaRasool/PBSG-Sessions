# Firecrawl: Turn Web Pages into Structured Results

## Why this is useful

Web pages are designed for people, not clean data pipelines. Firecrawl can discover and retrieve web content, while a carefully bounded prompt keeps the result focused and reusable.

It lets you search and scrape websites:

```text
Website
   │
   ├── Search
   ├── Scrape one page
   ├── Map/discover URLs
   ├── Crawl multiple pages
   ├── Extract structured information
   └── Interact with pages
```


MarkItDown is more naturally:

Convert example.com/pricing to Markdown.

Firecrawl can be:

Discover the pages on example.com, find the ones relevant to pricing, scrape those pages, and extract the information I care about.

MarkItDown makes different kinds of content LLM friendly. Firecrawl makes the web programmatically discoverable, crawlable, and extractable for an agent.

Make your MarkItDown demo:

```text
PDF/PPTX/YouTube → Markdown → reason over it
```

And your Firecrawl demo:

```text
Website → discover relevant pages → selectively scrape/extract information
```

Now they demonstrate two clearly different MCP capabilities.


## Setup

### 1. Add the Firecrawl MCP server

```bash
codex mcp add firecrawl  --url https://mcp.firecrawl.dev/v2/mcp
```

### 2. Inspect the configured connection

```bash
codex mcp get
```

## Try it

Copy this prompt into Codex:

```text
Use Firecrawl to scrape this page:

https://www.aicollective.com/events

Extract only the next 5 upcoming events.

For each event return only:
- Event name
- Date and time
- Location
- One-sentence description

Do not return the full page content or Markdown.
Do not follow any links.
```

## What to notice

- The prompt limits both the number of results and the fields returned.
- “Do not follow any links” gives the crawl an explicit boundary.
- The desired outcome is not a page dump; it is a small dataset someone can act on.
