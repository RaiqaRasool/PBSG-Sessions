# GitHub MCP: From an Issue to an Implementation Plan

## Why this is useful

An issue rarely contains everything needed to act. This example connects the issue discussion with a local repository so Codex can trace likely code paths and propose a plan—without changing anything.

## Setup

### 1. Check the current MCP connections

Run:

```bash
codex mcp list
```

### 2. Add GitHub and confirm that it appears

```bash
codex mcp add github --url https://api.githubcopilot.com/mcp/

codex mcp list
```

GitHub authorization is also required. Remove this initial connection before adding it again with authentication.

```bash
codex mcp remove github
```

### 3. Make your GitHub token available

Set this in `~/.tcshrc` or `~/.zshrc`:

```bash
export GITHUB_PAT_TOKEN="YOUR_TOKEN_HERE" -- this will work only for CLI codex for GUI codex you will have to set the launchctl env as show below
```

### 4. Add the authenticated connection

```bash
codex mcp add github \
  --url https://api.githubcopilot.com/mcp/ \
  --bearer-token-env-var GITHUB_PAT_TOKEN
```

### 5. Make the token available to the Codex desktop app

On macOS, `launchd` manages GUI application sessions. Run:

```bash
launchctl setenv GITHUB_PAT_TOKEN "$GITHUB_PAT_TOKEN"
```


## Try it in three steps

Start broad:

```text
Use the GitHub MCP server to list first 5 open issues in JeffersonLab/JANA2.
```

Then focus on one issue:

```text
Read issue #496 and summarize what the user is asking for. Do not modify anything.
```



Then connect the external issue to the local code:

```text
Read issue #496 using GitHub MCP.

Then inspect my local repository and identify which files and
parts of the code are likely involved.

Explain how you would implement the change, but don't modify
anything yet.
```

## What to notice

- The prompts move from discovery, to understanding, to planning.
- The final prompt names both sources of context: GitHub and the local repository.
- Every step remains read-only, making it a safe way to investigate unfamiliar work.
